# v6.0.0 — Watchlists

## Objetivo

Añadir condiciones personales persistentes sin crear un segundo sistema de identidad, alertas o destinatarios. Las watchlists se montan sobre `TelegramFavorite` y `FavoriteAlert`.

## Fuentes de señal

| Regla | Fuente | Condición |
|---|---|---|
| Precio | mejor oferta pública del ciclo HEALTHY | `current_price <= target_price` |
| Score | `opportunity_snapshots` | `score >= min_opportunity_score` |
| Mínimo histórico | `opportunity_snapshots.price_event` | `NEW_HISTORICAL_MIN` |
| CAV | `personal_opportunity_snapshots` | ganador `cav_member` y ventaja CLP >= umbral |

La evaluación sólo corre cuando la etapa de favoritos ya considera completa la cobertura del ciclo. Esto evita disparar watchlists a partir de una captura parcial o tienda BROKEN/DEGRADED.

## Deduplicación

- Precio, score y CAV usan estado booleano persistente y sólo notifican `false -> true`.
- Un valor que deja de cumplir vuelve el estado a `false`; si más adelante cruza nuevamente, puede notificar otra vez.
- El nuevo mínimo histórico guarda `precio_nuevo:minimo_anterior`, por lo que un mismo mínimo no se repite aunque el snapshot permanezca temporalmente en `NEW_HISTORICAL_MIN`.
- `FavoriteAlert.deduplication_key` continúa siendo una segunda barrera de entrega.
